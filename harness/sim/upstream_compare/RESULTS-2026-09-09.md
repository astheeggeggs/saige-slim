# strip vs upstream at N = 50,000, with a Firth-off arm (2026-09-09)

`strip` HEAD `bf600729` (`SAIGE.so` md5 `28d522d1…`) against upstream `main` 365deeff
(SAIGE 1.5.2, `SAIGE.so` md5 `2ec37f64…`) on the `sim50k` fixture
(`SAIGE-sim/harness/work/sim50k`: 50,000 samples, chr20, 210,515 markers, 210 genes,
pedigree-truth sparse GRM). Supersedes the timing half of `RESULTS.md` (2026-09-05);
62 commits separate the two HEADs. Build recipe and arm construction: `README.md`.

New in this run: a **Firth-off arm** (`--is_Firth_beta=FALSE`, `VARIANT=firthoff` through
`run_arm.sh`), and the gene tests re-measured after LEDGER #103/#104/#105/#106 landed
on 2026-09-08.

## 0. Controls, before any number

- **Self-reproduction (null).** 72 of 72 output-file comparisons byte-identical across
  the three timing reps, both builds, every workload (region, `.singleAssoc.txt` and
  `.markerList.txt` included). Each arm reproduces itself exactly.
- **Library provenance.** Every run's log records the SAIGE library R resolved and the
  `SAIGE.so` md5; the two arms never loaded each other's build (`results_20260909.tsv`
  columns `lib`, `so_md5`).
- **Machine state.** The paired block ran only after the 1-minute load fell below 2.5 on
  two consecutive 60 s polls with `CPU_Speed_Limit = 100`
  (`harness/work/upstream_compare/await_quiet_then_bench.sh`). An earlier attempt on a
  loaded box is recorded below as a warning, not as data.
- **Prediction registered before the run**: scratchpad `PREDICTIONS.md`, reproduced in
  section 4 with the two places it was wrong.

single-variant upstream/strip = **1.90x** binary, **2.04x** quant, **1.49x** binary Firth-off;
per marker 1319 vs 702 us (binary), 409 vs 199 us (quant), 576 vs 388 us (binary Firth-off).

**The 09-05 binary row (0.94x) is superseded, and the cause is located, not inferred.**
Commit `b11e6b07` (2026-09-06) made three changes, each gated byte-identical on these
scans, and its own message records their measured effects: `KernelWorkspace` reuse on
`MarkerScratch` (1-thread user 240-268 -> 205 s), the `countOneMarker` QC pre-screen
(quantitative scan 60-65 -> 45 s), and `--firth_solver=closed`, now the default (-27% on
the binary scan). Step 1 and the gene tests, which none of the three touches, are
unchanged from 09-05 -- which is the specificity check on that attribution.

Corroboration in the system time: upstream's binary scan spends 16.5-18.9 s of **sys**
with Firth on and 4.4-4.6 s with it off, i.e. ~14 s of kernel time in Firth alone -- the
mach VM map/unmap churn of >127 KB Armadillo temporaries that `KernelWorkspace` removed.
Strip shows no such term (3.8-4.1 s either way).

`maxRSS` strip ~2790 MB vs upstream ~350-380 MB on every scan: resident pages of the
mmap'd 2.6 GB `.bed`, not allocation (`SAIGE_PLINK_NO_MMAP=1` peaks at 312 MB, output
byte-identical). Unchanged from 09-05; documentation item.

## 2. The cost of Firth, within each build

| workload | build | Firth on | Firth off | saved |
|---|---|---|---|---|
| single-variant `y_binary` | upstream | 245.43 | 116.11 | 129.3 s (52.7%) |
| single-variant `y_binary` | strip | 137.91 | 76.75 | 61.2 s (44.3%) |
| gene tests `y_binary` | upstream | 216.55 | 206.64 | 9.9 s (4.6%) |
| gene tests `y_binary` | strip | 157.48 | 153.58 | 3.9 s (2.5%) |

Firth fires on **7,891 / 70,709** markers in strip and **6,832 / 70,701** in upstream
(the 1,059 difference is LEDGER #28 suppressing upstream's own AF > 0.5 Firth count, the
"~1,000 fits" `b11e6b07` records). Per Firth marker that is **7.8 ms strip vs 18.9 ms
upstream** -- a 2.4x gap in the Firth kernel itself, which is `--firth_solver=closed`
plus the workspace reuse.

**Firth-off is the like-for-like binary comparison, and it makes strip's lead SMALLER,
not larger** (1.78x -> 1.51x). Leaving Firth on flatters strip, because Firth is where
strip's advantage is largest. This is the reverse of the prediction (section 4).

## 3. p-values

### 3.1 Firth changes no p-value anywhere (control)

Established four ways, on printed bytes (`compare_firth.R`, columns read as character):

| build | workload | columns that move | rows |
|---|---|---|---|
| strip | single-variant `y_binary` | BETA, SE only | 7,891 / 70,709 |
| upstream | single-variant `y_binary` | BETA, SE only | 6,832 / 70,701 |
| both | single-variant `y_quant` | **none** -- whole file byte-identical | -- |
| both | gene region file | **none** -- whole file byte-identical | -- |
| strip | `.singleAssoc.txt` | BETA, SE only | 942 / 9,049 |
| upstream | `.singleAssoc.txt` | BETA, SE only | 686 / 8,084 |

Mechanism, `src/SAIGE_test.cpp:942-1017`: Firth is entered after `pval` is final and
writes only `t_Beta`/`t_seBeta` (`t_seBeta = |t_Beta| / |t_qval_Firth|`). Both branches
pin `|BETA|/SE = |qnorm(p/2)|`, so the BETA and SE ratio distributions are identical to
the printed digit and Z is preserved exactly -- a second, independent reason p cannot move.
The region file is byte-identical because Firth is not implemented for burden effect
sizes under `r.corr == 0`; `R/SAIGE_Test_main.R:682-688` prints exactly that.
All twelve strip-vs-upstream comparisons are numerically identical between the Firth-on
and Firth-off arms (every Pearson, max |d| and tag count).

Effect-size movement, where Firth does act: common markers median ratio 1.006
(IQR 0.961-1.082, range 0.445-6.14); the rare single-in-group markers median **2.02**
(IQR 1.70-2.47).

### 3.3 The gene-test cells the 09-05 tagger could not explain are LEDGER #103-#106

The comparator's reconciliation predates those fixes, so it can only flag them. Located
two ways, both decisive:

**Quantitative, arithmetic.** The burden-variance quotient (strip/upstream) has median
**1.005301**, against a variance-ratio row quotient of **1.00530** -- a match to five
decimal places. On quantitative the whole gene-test difference is the step-1 variance
ratio, and strip's larger variance makes it *less* significant (2,416 cells negative,
492 positive).

**Binary, by re-running the pre-fix code.** The binary variance-ratio rows are all within
0.14% of 1, yet the burden variance is off by **1.44%** the other way -- which the ratios
cannot produce. Re-running strip at `cca6b497` (pre-#103, scratch lib; all three of
`get_SKAT_pvalue`, `get_newPhi_scaleFactor_traitType` and `setSparseSigma_new` verified
different from HEAD by `deparse`):

| gene tests vs upstream | UNPREDICTED | max abs dlog10 P | cells matching a VR row |
|---|---|---|---|
| strip HEAD, `y_binary` | 20 | 0.2625 | 141 / 3,118 |
| strip pre-#103, `y_binary` | **0** | **0.0183** | **3,118 / 3,118** |
| strip HEAD, `y_quant` | 3 | 0.0568 | 1,724 / 3,115 |
| strip pre-#103, `y_quant` | **0** | **0.0270** | -- |

0.0183 is the 09-05 table's binary gene figure (0.018) to the printed digit, so removing
the four fixes reproduces that baseline and independently re-validates it.

Isolating the fix set on the **same model** (pre-#103 vs HEAD): burden variance median
**0.985636**, against the strip-vs-upstream quotient median **0.9856363** -- identical to
six decimal places, with max |dlog10 P| 0.2625 both ways. The pre-existing per-fix ladder
(`harness/work/null50k-20260908/diff-binary.txt`) says which of the four: #103 moves **no**
p-value (only `BETA_Burden`/`SE_Burden`, via `kappa_w`), #106 moves many by ~0.1%, and
**#104/#105** carries it, median burden-variance factor 0.9878.

Direction: strip's binary burden variance is smaller, so strip's gene p-values are
smaller -- 2,810 cells more significant against 265 less. That is #104's stated mechanism
("the naive GLM variance -- no GRM, no variance ratio -- wherever those two reduce it").

## 4. Where the registered prediction was wrong

1. **"Upstream fires Firth on ~3x fewer markers, so it will save less."** Wrong twice
   over. The 3x was the AF > 0.5 *subset* (1,633 vs 569) read as genome-wide; the real
   gap is 1.15x (7,891 vs 6,832). And upstream saves *more* (52.7% vs 44.3%) because its
   Firth fit costs 18.9 ms/marker against strip's 7.8 ms.
2. **"upstream/strip on binary will RISE above 1.2x once Firth is off."** It falls,
   1.78x -> 1.51x. The premise -- that Firth-on flatters *upstream* -- had the sign
   backwards.

Correct: Firth is a p-value no-op (section 3.1); the gene-test surprise on both traits
and its direction; step 1 and gene-test ratios unchanged from 09-05.

## 5. Reproducing this

```sh
bash harness/sim/upstream_compare/run_pvalue_phase.sh          # 24 runs, MODELS=own
bash harness/sim/upstream_compare/bench_firth.sh 3             # paired timing, refuses if load > 2.5
bash harness/sim/upstream_compare/compare_all.sh 0 1 base      # comparators + plots
bash harness/sim/upstream_compare/compare_all.sh 0 1 firthoff
Rscript harness/sim/upstream_compare/analyse.R harness/work/upstream_compare/results_20260909.tsv
```
`run_arm.sh` gained `VARIANT` (tags a flag change made through `S2EXTRA` so its logs,
outputs and TSV rows do not collide) and a `variant` column in the TSV; `compare_all.sh`
and `analyse.R` are variant-aware; `compare_firth.R` is the within-build Firth control.
Per-row TSVs in `harness/work/upstream_compare/cmp/`, plots in `plots/*_own_{base,firthoff}*.png`.

**Trap for the next session.** `pgrep -f <script>.sh` matches any process whose command
line contains that string, including a monitor whose own command is a loop over that
pgrep. Two waiters here deadlocked on each other and idled 33 minutes. Wait on a PID, or
on a marker file.
