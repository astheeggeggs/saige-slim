## #142 -- the evidence for the owner's decision

The question: at an in-sample N where some `mac:` rungs admit every marker,
what should `p_FlexRV` combine? Four candidates were named on the row and in
the request: (a) an N-aware warning only, (b) drop the a-priori degenerate
rungs before pooling, (c) keep the paper's arithmetic and document, (d)
something else (the `dedup` and `axis` rules of `pool_rules.R`).

**The mechanism is arithmetic, not data.** Ingest admits a marker only if its
folded MAF is at or below `--flexRV_maxMAF`, so every admitted MAC is at most
`2*N*maxMAF`, and the kernel is `MAC <= t`; a rung `t` at or above the bound
is the all-ones vector, i.e. `unw`. With the default ladder and the paper's
`maxMAF = 0.001`, rung `t` is degenerate for every N at or below `500*t`:

| rung | degenerate at N <= |
|---|---|
| MAC500 | 250,000 |
| MAC200 | 100,000 |
| MAC100 | 50,000 |
| MAC50 | 25,000 |
| MAC25 | 12,500 |
| MAC10 | 5,000 |
| MAC5 | 2,500 |
| MAC3 | 1,500 |
| MAC1 | 500 |

At the paper's N (423,614 unrelated, `docs/design/flexrv-design.md`) the bound
is 847, so NO default rung is degenerate and the shipped rule `all` IS the
paper's statistic there. The paper's own pipeline converts its MAC rungs to
MAF cutoffs with a hardcoded N = 100,000 (`amc_run_saige.py`, design doc), so
it is not a parity target and does not settle the question.

**Measured.** On the bundled fixture (N = 1,000, `maxMAF = 0.01`, bound 20):
80 of 192 sets duplicate their `unw` row (5 rungs x 16 score transforms) and
the pooled row is 1.45x the value over distinct rows on GENE1 and 0.966x on
GENE2 -- the sign is not fixed. At N = 50,000 (`harness/sim/flexrv_study`,
`pool_rules.R`, 210 genes x 16 arms, first run appended to
`handoff-2026-09-13-evening-six-rows.md`): 48 of 192 sets are a-priori
duplicates and a median of 69 are value-identical (the other ~21 are data
driven: a score transform with no admitted marker, or `lof` equal to `unw`
when every marker is LoF). Under every rule the null ECDF at 0.05 and 0.01 sits
inside the binomial interval and no rule differs from `all` by more than the
interval's width; Bonferroni detections among 63 causal genes are identical or
within one; Spearman rank agreement with `all` is 0.95-0.99; the per-gene
ratio `p_apriori / p_all` has quartiles 0.96 and 1.05 with tails 0.18 and
5.2. So the choice is invisible in aggregate and up to 5x on a single gene,
in either direction: it is a question of DEFINITION, not of calibration or
power.

**Cost.** `apriori` skips 48 of 192 sets at 50k and 80 of 192 on the fixture
(25 % and 42 % of the BURDEN work); it is computable from N and the flags
before a marker is read.

**Assessment of each candidate.**
- (a) warning only: moves nothing, costs nothing, compatible with any later
  choice; leaves `p_FlexRV` depending on N through the duplicate count and the
  score axis re-weighted (each score transform carries 6/12 of its own `unw`
  burden on the fixture instead of 1/12).
- (b) as `apriori`: deterministic from (N, maxMAF, ladder); equals `all` bit
  for bit whenever no rung is degenerate (the paper's regime) and is "the
  paper's statistic over the rungs that can differ at this N" elsewhere;
  `p_FlexRV` stops depending on N through duplication; 25-42 % less work; the
  omitted set names make the output self-describing and the #127 sidecar
  already records the rows combined. Blast radius: the four FlexRV goldens
  P58-P61 move (fewer rows; on the P58 golden, recomputed from its own
  rows, GENE1's pooled row 0.139077 -> 0.095698 and GENE2's 0.907609 ->
  0.939030), the helper's fixture fact "MAC25..MAC500
  duplicate `unw`" and `test-step2-flexrv.R`'s row-for-row test invert (they
  would need a rung BELOW the bound but above every marker's MAC, i.e. a
  custom ladder), the CLAUDE.md FlexRV trap is reworded. Users comparing to a
  run of the shipped code see fewer rows and a different `p_FlexRV`.
- (b) as `dedup` (value-identical rows): also drops the ~21 data-driven
  duplicates per region, which are legitimately identical TESTS rather than
  degenerate transforms; region-dependent, harder to state. Not recommended.
- (c) document only: (a) without the warning; nothing changes.
- (d) `axis` (weighted CCT): keeps every row and changes the arithmetic to a
  statistic the paper does not define; measured indistinguishable from
  `apriori`. Not recommended.

**Recommendation: (b) as `apriori`, with (a)'s warning line as the
disclosure** (printed once per run, naming the bound, N, and the rungs
dropped), one commit. The characterization the request specified inverts
cleanly: the number of sets dropped equals (rungs at or above `2*N*maxMAF`) x
(score transforms) -- 80 on the bundled fixture, 0 when `--flexRV_maxMAF` is
raised enough -- and no emitted row is a rung at or above the bound. The
counter-argument that should weigh: the goldens move and the row-for-row test
inverts, whereas (a) alone moves nothing. Implementation note: N is the
model's sample count, known after `ReadModel` and before set composition; the
spec is expanded in `R/SAIGE_SPATest_Region.R` (`flexrvTransformTable`), which
is where the rungs would be dropped.

## #142 -- what landed (2026-09-14, after the owner chose option b)

- `flexrvTransformTable(..., N = NULL)` (`R/FlexRV.R`): with N, drops every
  `mac` rung with `param >= 2 * N * maxMAF` before the table is built, refuses
  a spec left with no MAF transform by name, returns `dropped`, `bound`, `N`.
  `SAIGE.Region` passes its own `n` (`length(mu[[1]])`, the count C++ is
  handed) and warns once per run: `FlexRV: at N = 1000 and
  --flexRV_maxMAF=0.01 every admitted marker has MAC <= 20, so the MAC rungs
  25, 50, 100, 200, 500 would weight every marker 1 and duplicate 'unw'; they
  are dropped before the sets are composed (LEDGER #142): 112 sets (16 score x
  7 MAF), not 192`. C++ is untouched: it only ever iterated the table's rows.
- **Goldens, predicted from the old goldens' own rows before the run**: P58,
  P59, P61 193 -> 113 rows per gene; on P58 GENE1's pooled row 0.139077 ->
  0.0956982 and GENE2's 0.907609 -> 0.93903; P61 byte-identical to P58; P60
  (no `mac` rung) byte-identical to its committed bytes; every surviving row
  byte-identical to its old self. Each generated twice into separate files
  and `cmp`-identical. The distinct (p, beta, se) count per gene is 111 of
  112 (was 111 of 192): dropping exact duplicates changes what is emitted,
  not what the fixture can tell apart.
- **Tests**: `test-step2-flexrv-rungs.R` is the characterization the request
  specified (80 dropped on the fixture, named in the warning, absent from the
  output; 0 dropped at `--flexRV_maxMAF=0.26`, bound 520, all 192 emitted);
  `test-unit-flexrv.R` pins the bound arithmetic (a rung EQUAL to the bound is
  degenerate, the paper's N drops nothing, 50k drops three, the
  all-degenerate refusal, N validation); the row-for-row duplicate tests in
  `test-step2-flexrv.R` and `test-invariants-goldens.R` became absence
  assertions. The external weight-line route in `helper-step2-flexrv.R`
  deliberately keeps all 192 lines: the 112 shared names reconcile row for
  row and the 80 rows the internal run no longer composes are asserted equal
  to their `unw` row -- the second computation that the dropped sets were
  duplicates and nothing else. The BURDEN memo's `served` is asserted `<= 1`
  (one printed-equal pair remains, GENE2 lof_MAC5 / lof_MAC10), never `>= 1`.
- **Docs**: roxygen, `man/` (regenerated with `load_code = roxygen2::load_source`,
  which does not compile), CLI help, README, CLAUDE.md's FlexRV trap,
