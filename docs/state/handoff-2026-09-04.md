## The one thing to take from it

**An adversarially-verified finding is a hypothesis about WHETHER something is
wrong, not about WHAT is wrong.** All three findings were real -- none was
dropped -- but two were materially mischaracterised, and in both cases the
reproduction, not the review, is what corrected them:

* **#61** was written as "a bin would be emitted with all its markers already
  discarded". It is not empty: it is a **byte-for-byte duplicate of the bin
  below it**, which looks like an answer rather than like a failure. That is a
  worse defect and a different detection strategy -- a test that only checked
  the bin was non-empty would have passed at unpatched HEAD, which is why
  `test-step2-maxmac-bins.R` asserts the new bin holds markers the bin below
  does not.
* **#54** was written as "step 2 also skips 3 bytes but at least routes through
  a reader class". Step 2 in fact always checked the MODE byte; what it never
  checked were the two MAGIC bytes. And step 1 was worse than recorded, not
  better -- it checked neither, and a genuinely sample-major `.bed` produced a
  wholly wrong GRM at exit 0.

## Traps and techniques learned here

* **A size check and a header check are not substitutes.** On
  `genotype_100markers`, `M*ceil(N/4)` and `N*ceil(M/4)` are BOTH 250,000, so a
  sample-major `.bed` is exactly as long as the SNP-major one and #58/#60's size
  check sees nothing. The test asserts that equality explicitly so the point
  cannot be lost.
* **`plink2` is an external oracle for malformed-file work, and it is already a
  pixi dependency.** It refused the bad-magic file and correctly transposed the
  sample-major one -- which is what proved the hand-built sample-major fixture
  was a legitimate dataset rather than a corrupt one. Without that control the
  #54 reproduction would only have shown SAIGE reading garbage from garbage.
* **A golden whose bytes duplicate another golden can still gate something
  real.** P35 is byte-identical to P2 in every file, and that identity IS
  LEDGER #51 (the region path never consults `m_isFastTest`, so the escalated
  pass recomputes what the fast pass had). It pins the other WRITER: under
  LEDGER #50 this run lost all 19 single-variant rows at exit 0 while P2 stayed
  green. CLAUDE.md's "a golden that reproduces P1 gates nothing" is about the
  same PATH, not the same BYTES -- `make_goldens.sh` now says so at the block.
* **Strengthening a guard can move an unrelated assertion.** #62's contiguity
  check subsumes the old monotonicity check and fires FIRST, so an existing test
  that expected "ordered from 1 to 22" started getting the new message. The old
  check keeps its own coverage on `c(2, 2, 1)`, where every chromosome IS
  contiguous.
* **How to satisfy CLAUDE.md's `option_list` rule when ADDING an option**, not
  just when restyling: eval the `option_list` block out of the script before and
  after, dump `(short_flag, long_flag, action, type, default, dest, help)` per
  option, and diff. Here: 58 existing options metadata-identical, exactly one
  added. The capture script is six lines and is worth rewriting rather than
  eyeballing a diff.
* **Reproduce at the cheapest layer that shows the defect.** #60 and #54 were
  driven through `setgeno` directly rather than a step-1 fit -- seconds instead
  of minutes, and the marker counts are readable. #62 is a pure R function and
  needed no build at all.

## Traps learned here, all of which cost a full cycle

* **A worker function must be defined at TOP LEVEL.** R serializes a closure with
  its enclosing environment, so a `clusterApply` worker defined inside the driver
  shipped the whole `outList` per task: 0.97x at 4 workers, sys CPU 63 s. Hoisted,
  it is 1.29x and 30 s. If a worker needs a value, put it in the job.
* **Check the obvious suspect before refactoring around it.** The three-pass
  drive of `region_postprocess` looked like the reason the first parallel version
  was slow. Measured in isolation: 180.9 s vs 180.6 s. Free. That check saved a
  rewrite of the most intricate function in the package.
* **`--markers_per_chunk_in_groupTest` cannot force chunking** on the bundled
  fixtures. Each region has three or four non-ultra-rare markers, but the
  ultra-rare collapse always appends a chunk, so `nchunks == 2` and every
  non-BURDEN group golden already exercises the disk round trip. The FAILURE is
  what no golden reaches.
* **Check the load before timing.** The first `--nThreads` benchmark ran at load
  6-8 and read 0.97x/1.06x; the same build at load ~4.3, interleaved, read
  1.30x/1.28x with ~1% replicate spread.
* **`ledger.py` counts rows with >= 5 cells.** Editing a row's status by string
  surgery can eat a `|` and silently drop the row from the count -- the total
  went 59 -> 57 and only the total gave it away. Check `ledger.py open` after any
  edit.
